# CallGuard delivery plan

This plan tracks the eight challenge stages. PR #1 and PR #2 were open when this plan was written. Their CI runs cover the previous detector and guard work. The Stage 3 changes are local in the classifier branch. [Detector PR #1](https://github.com/Farazuddin178/callguard/pull/1), [Guard PR #2](https://github.com/Farazuddin178/callguard/pull/2), [latest successful CI on the branch before Stage 3](https://github.com/Farazuddin178/callguard/actions/runs/45999561441).

| Stage | Delivered | Remaining work | Acceptance criteria |
| --- | --- | --- | --- |
| Understand | Documented the audience, scam tactics and official figures, speakerphone scenario, privacy and misuse threats, legal note and device risks. [Understand](understand.md). | Capture findings from tests on representative phones during Test. | Each figure has an official source and a date or reporting period. The scenario explains who starts listening and why speakerphone is needed. The threat model covers covert listening, stalkerware and false reassurance. |
| Plan | Mapped all eight stages to deliverables, evidence and acceptance checks. [Plan](plan.md), [evidence pack](evidence/README.md). | Update the plan with Stage 3 PR and CI links when available, then record the remaining checks as they finish. | Each stage has a concrete deliverable, evidence of completed work, remaining work and criteria that can be checked. |
| Build | Implemented the multilingual rule engine, on-device speech, local guard flow and browser classifier. [Rules](../src/detect/rules.ts), [session](../src/session/guard-session.ts), [trainer](../training/train.py), [browser model](../src/detect/model.ts). | Validate the same-phone speakerphone flow and local warnings on real devices. | The user controls the visible mic session. Telugu, Hindi and English have warnings with reasons. The model runs offline, contributes at most 20 points, and every red alert has a rule hit. |
| Test | Established hit and near-miss tests, a frozen 130-call evaluation, scikit-learn parity checks, privacy tests and Playwright smoke tests. [Rule tests](../tests/rules.test.ts), [evaluation](../tests/eval.test.ts), [parity](../tests/model.test.ts), [privacy tests](../tests/privacy.test.ts), [browser tests](../tests/e2e/). | Run the standard build and Playwright suite for Stage 3 outside the sandbox. On representative Android and iOS phones, record call capture, Whisper backend, chunk timing and time to warning in all three languages, including unsupported configurations. | Lint, typecheck, tests and production build pass. At score 70, combined recall is at least 90% and FPR is at most 10%. All 30 parity cases match within 1e-6. The browser mock reaches red, and device results document speakerphone and offline behaviour. |
| Review | Recorded two detector review rounds and a guard-flow review. [Review evidence](evidence/README.md#review), [guard review](evidence/README.md#review-guard-flow). | Request `@codex review` on the classifier PR. Ask the independent reviewer to check data separation, inference parity and privacy on the changed path, then record dispositions. | An independent review covers the changes, and findings are fixed or documented with their impact and disposition. The evidence links the reviews and verification. |
| Document | Documented privacy, user flow, speech-check setup, evaluation, reproducible training and limitations. [README](../README.md), [training guide](../training/README.md), [evidence pack](evidence/README.md). | Add verified device results, release links and any screenshot filenames after verification. | A new reader can run the app and trainer, understand the data boundary and interpret the metrics. Evidence identifies the Codex features used and the model for each recorded stage. |
| Ship | Configured the static Vercel project and confirmed the guard preview status on PR #2. [Vercel config](../vercel.json), [guard preview deployment](https://vercel.com/farazs-projects-9cd6b502/callguard/BVse5sMY1rimav7EuZ9ee4i9PJ2G). | Verify the classifier preview from the reviewed change, merge approved changes and verify the production URL. | The static HTTPS deployment opens and installs as a PWA, the shell reopens offline, and a supported phone can run a cached speech model and reach the localized warning. |
| Automate | Configured push and PR checks and PR evaluation comments. Added a pinned Python 3.13 job to retrain and check both exports. [CI workflow](../.github/workflows/ci.yml), [PR report workflow](../.github/workflows/eval-comment.yml), [baseline guard PR CI](https://github.com/Farazuddin178/callguard/actions/runs/45998809759). | Verify the new classifier job and side-by-side PR comment on GitHub. | Push and PR checks run lint, typecheck, unit tests, evaluation and build. Retraining fails on substantive export drift. The PR comment includes the overall and per-language/script comparison. |
